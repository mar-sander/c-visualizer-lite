# C Code Visualizer Lite — 四則演算 学習版

授業用の新UI統合実証版です。`index.html` をブラウザで開くと、C言語の対応範囲で int / float / double / char scalar の基本四則演算、代入、main直下の基本if／if-elseと最大2階層の入れ子if／if-elseの処理STEPを可視化できます。printfは%d／%c／%f／%lfと小数点以下0～20桁の%.Nf／%.Nlfによる出力、main直下の単一変数scanfは%d／%f／%lf／%cに対応します。printfでfloat・doubleを表示する場合は%f（%lfも使用可能）を使い、%dは整数表示、%cは文字表示です。INPUT欄ではscanf 1回につき1行を入力します。1行に1つの文を書いてください。Cコンパイラや正誤判定の代わりではありません。

- CODEに書く → RUN → RESULTの出力・最終変数を見る → 「流れを見る」からSTEPをたどる。
- RUN後は、STEPがあるコード行の行番号から、その行の最初のSTEPへ移動できます。編集すると古い結果は閉じます。
- SECRET CODEで解除するSAMPLEには「配列の基本」と「配列とfor文」があります。「配列とfor文」は添字iを0～4へ進め、a[i]へi * 10を代入して出力します。選択では実行せず、RUNで0／10／20／30／40の5行と最終配列[0, 10, 20, 30, 40]を確認できます。
- CodeMirror 5.65.20 は `vendor/codemirror/` に同梱し、ネット接続なしでもエディタが起動します。ライセンスは同フォルダの `LICENSE` にあります。

解析エンジンは `mar-sander/c-visualizer` の main `7d2e4de9d984090b75d1b2b77554479489a94469` を複製し、STEP生成時の出力・変数スナップショットと、解析結果のUI引き渡しだけを追加しました。UIの配置・配色は `mar-sander/ui-lab-c-visualizer` の main `c68f6e0a6cfc6c53c6505fbfa0a862c159ea96dc` を基準にしています。

`tests.html` は本体から複製した回帰テストです。ブラウザで開くと同じ `script.js` を読み込み、従来の解析結果を検査します。

## L-ARRAY1 配列の箱表示

main直下の1次元int配列（長さ1～100）、未初期化・完全初期化・部分初期化・`{0}`、定数添字による要素代入と読出しを、RESULT／VARIABLESとFLOWで確認できます。部分初期化で省略した要素は0、未初期化は「—：まだ値を入れていない要素」です。長い配列はカード内で横スクロールします。

FLOWには宣言・アクセスに関係する配列だけを、そのSTEPの値で表示します。「参照」「代入」のラベルは当該STEPだけに付き、最終状態には残りません。通常のscalar変数とも共存します。解析結果の`arrays`と`steps[].arrayViews`は値のコピーと`initialized`フラグを持ち、未初期化は`values`内のnullとfalseで明示します。エンジン内部のSymbolは渡しません。

履歴は既存JSON v1の`variables`文字列ペアへ、例`["a (int[3])", "[—, 7, —]"]`として最終状態を保存します。コード復元で自動RUNはしません。保存容量やimport上限に収まらない場合は保存失敗を表示し、実行結果と既存の保護履歴を維持します。100要素でも数値文字列は通常の10000文字上限に収まります。

## L-ARRAY2 配列とfor文

宣言・初期化済みのint変数を単純添字にした参照・代入と、main直下forの直接本体での配列利用に対応します。例は `a[i] = i * 10;`、`x = a[i];`、`printf("%d\n", a[i]);` です。範囲外や未初期化要素の読出しでは停止し、その先の代入・出力を実行しません。

FLOWの参照・代入STEPでは、実行時点で解決した `a[i] → a[3]` と対象の箱を表示します。代入した箱には変更前→変更後も表示し、未初期化の「—」を0と区別します。前後STEPへ移動しても各時点の値・添字・出力が復元されます。

forの反復説明は6回までは全件、7回以上では先頭3回＋最後1回を表示し、間を省略STEPで表します。計算・代入・出力自体は省略しません。省略STEPには省略区間終了時（最後に表示する反復の開始直前）の全配列とscalar変数を表示し、アクセスの強調は残しません。通常のSTEPは従来どおり関係する配列だけを表示します。省略STEPの `arrayViews` も独立したコピーです。代入accessにはJSON互換の `previousValue`／`previousInitialized` を追加しました。

反復の安全上限は既存どおり500回です。501回目の本体へ入る前に安全停止します。これはC言語の制限ではありません。履歴のJSON v1・ロック・復元時の自動RUN禁止は維持します。

if／else if／while内、for内if、入れ子for内の配列操作、添字式、複数要素を読む式、配列scanf、要素の `++` や複合代入、他型・多次元配列などの未対応構文は拡張していません。大規模な解析器や圧縮機構の再設計は行っていません。

`tests.html` に配列×forの境界・安全停止・snapshot・製品UI・履歴テストを追加しています。既知のUI-FONT1 5件／L-UI15 2件は別Stageの課題として残っています。検証結果と対象ファイルのハッシュは納品の検証記録を参照してください。

UPDATEの日付は正式公開時の実際の日本時間の日付を手動設定します。実装・プレビュー段階では既存の日付を維持し、公開承認後に`index.html`の表記1か所だけを更新します。

## L-ERR1 エラー診断の位置情報

入れ子for／if／else if／whileの事前検査では、実行を止める外側の範囲と、未対応・不正な記述がある原因行を分けて保持します。原因行は`cVisualizerLiteResult.diagnostics`の`lineNo`（1始まり、全体へのヒントはnull）としてUIへ渡し、エラーメッセージとエディタの赤表示を揃えます。既存の`warningText`とSTEPの停止位置は維持します。

波括弧の不一致は対応する開き括弧または余分な閉じ括弧の行を示します。再宣言、不足したreturnのセミコロン、printfの空引数も診断し、printf引数の文字定数内のカンマ・括弧は区切りとして扱いません。C言語の対応構文は追加していません。

`tests-error-diagnostics.html`は、同じディレクトリの製品をiframe内でRUNする診断・強調表示・安全停止の自動テストです。既存の`tests.html`等とともにHTTPで配信して開くと実行できます。構造の事前検査は未選択側を含み、実行時診断は選択された処理だけを評価します。これはCコンパイラの完全な構文・意味検査ではなく、対応範囲外の正しいCにも「未対応」と表示します。

## L-ARRAY4 汎用の配列参照と代入

同じ式内の複数配列参照、配列同士の比較、配列から配列への代入、既存の最大3階層for内での配列操作、各forの直接if／if-else内の配列操作に対応しました。L-ARRAY2の上記未対応一覧のうち、これらの制約を置き換えます。教材05(3)は通常の式・比較・代入・for・ifの組み合わせで実行され、ソート専用処理はありません。比較演算子を変えた昇順や、最大要素の添字を保持する選択ソートにも同じエンジンを使えます。

FLOWでは比較左辺／右辺、配列間代入の代入元／先を区別します。同一要素のread/writeも読出し値を保持し、書込み後の箱と変更前後の値を表示します。STEP圧縮は表示だけに適用し、各代入を実行した後の独立snapshotを維持します。

添字は引き続き整数literalまたは単一int変数です。`a[j + 1]`、配列要素更新、forヘッダの配列参照、while内・入れ子if内・else-if条件チェーンの配列操作、他型や多次元配列は未対応です。未対応構文は事前検証、範囲外・未初期化・不正型は実行時検査で停止します。既存テストのうち対応構文の拒否を期待していた8件は正常実行の期待値へ更新し、4件は引き続き未対応となる式／更新の安全停止を検証する形へ変更しました。
